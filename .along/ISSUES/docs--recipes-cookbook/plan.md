# Plan: dynstruct Cookbook (task-oriented recipes)

Issue: `docs--recipes-cookbook` (dynstruct `.along/`, in-progress)
Execution Mode: Direct (docs only, no source code changes)

## Context

The dynstruct docs are reference-shaped (concepts, API, contracts) and largely agent-oriented.
A developer evaluating the framework who asks "how do I validate a form?" or "how do I pass data
parent -> child?" gets many granular search hits and no single answer. The scenarios exist in the
Storybook stories, the Astro demo, the tests and the mempart webapp/ui-core, but nowhere as short
recipes. Goal: add a new Cookbook section next to the existing docs (existing pages untouched,
except additive cross-links), plus a clear explanation of the two meanings of `children`.

## Format

Each recipe follows one template:

- **Task** (one line, "I want to ...")
- **Solution**: minimal working code (struct + def + view), current API only
- **How it works**: 2-5 lines
- **Gotchas**: bullets
- **See also**: reference topic link + story/demo source link (`../src/_stories/...`, `../demo/src/...`;
  the VitePress config already rewrites `../` links to GitHub)

Language: English (matches the rest of the docs). ASCII typography, fenced code with languages.

## Files (all new, under `src/packages/dynstruct/docs/`)

1. `topic--cookbook.md` - landing page: "I want to..." table mapping tasks to recipes, the recipe
   template, the canonical component skeleton (`let c`/`let m`, `useComponent`, `toReact`).
2. `topic--cookbook-components.md` - define a component; public vs private struct
   (`ComponentStructExt`); defaults vs params; computed props; actions; mount in React
   (`toReact`, `$id`, `$key`); provide the bus at app root; React content in props (`reactive: 'ref'`);
   **"Two kinds of `children`"** (`c.children` vs React `props.children` / `ComponentViewProps.children`).
3. `topic--cookbook-data-flow.md` - one-way parent -> child (`bind`); two-way (`bindProp`, nested path);
   custom get/set; `ValueConverter`; child -> parent intents over the bus (`FromDescendants`) instead of
   callback props; call a child's action; react to prop changes (`onChangeX`) and the bound-prop case
   (use an effect); reload when inputs change (effect + key); external store (`fromExternalStore`).
4. `topic--cookbook-forms-validation.md` - per-prop validator + `mapToEdit` + `m.$.propState`;
   validate on change/blur; async validator; `c.validate()` before submit; cross-field `onValidate`;
   server errors into the form (`HttpClientError.code`); submit button disabled/loading; reset a form
   when a dialog opens; manual `errors` map alternative.
5. `topic--cookbook-composition.md` - `React.FC` fragments; list of child components (factory
   children + `key`); conditional/lazy children; pass a child into another child's slot; parent-controlled
   dialog; global dialog opened over the bus; reactivity modes for big arrays (`shallow`/`ref`).
6. `topic--cookbook-messaging.md` - custom msg struct + headers; `msgScope`; send/subscribe;
   request/provide; react to `out`; topics; parent/child scoped messages; replayed state channels;
   global notices (`APP.NOTICE`); talking to the bus from plain React (with cleanup); bus outside React.
7. `topic--cookbook-services.md` - API client via `ServiceProvider` + adapters (`ToMsgStruct`,
   `payloadFn`); `HttpClient` with `useAuth`; loading via `m.$.pendingRequestCount`; debounce + stale
   responses (abort / sequence guard); service implemented as a component; storage service.
8. `topic--cookbook-auth-navigation.md` - typed routes (`createNavigationRoute`); `APP.NAV.GOTO`;
   `NavLink`; reading nav context; `SecurityService` sign-in/out; auth guard page (`AUTH.ENSURE` /
   `INFO.GET`); custom auth handlers (`useConventions: false`).
9. `topic--cookbook-errors-testing.md` - `onCatch` and the boundary rules; render errors +
   `fallbackView`; `m.$.errors`; global `APP.ERROR` overlay; `c.run`; testing a component with a
   real bus and fake providers (`msgBus.provide` on API channels).
